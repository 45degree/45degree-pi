# Glossary

按字母顺序排列的关键术语。

- **µop (Micro-operation)** — x86 CISC 指令译码后拆分成的 RISC 风格微操作；microfusion 和 macrofusion 可节省流水线带宽 (Ch 3, 4)
- **AVX / AVX-512** — Intel 的宽向量指令集，256/512 位；支持单指令多数据操作 (Ch 3, 9)
- **AMX (Advanced Matrix Extensions)** — Intel 和 Apple 各自的矩阵加速指令，用于 ML 工作负载 (Ch 3)
- **Bad Speculation** — TMA L1 分类：因分支误预测或 machine clear 造成的浪费流水线 slot (Ch 6)
- **Backend Bound** — TMA L1 分类：执行资源不足以处理已分发的 µops（Memory Bound + Core Bound）(Ch 6)
- **BOLT / Propeller** — 二进制后链接优化工具：基于采样数据重排代码布局，比 PGO 更灵活 (Ch 11)
- **BPU (Branch Prediction Unit)** — 分支预测单元：动态预测分支方向，利用局部和全局关联性 (Ch 3)
- **BRBE (Branch Record Buffer Extension)** — ARM 的分支记录机制，类似 Intel LBR (Ch 6)
- **BTB (Branch Target Buffer)** — 缓存分支目标地址的硬件结构 (Ch 3)
- **Cache Coherence** — 多核间缓存一致性协议（MESI/MESIF/MOESI），确保数据一致性 (Ch 3, 13)
- **Cache Line** — 缓存间数据传输的最小单位，典型 64 字节；Apple L2 使用 128 字节 (Ch 3)
- **Change Point Detection (CPD)** — 基于统计模型的性能回归检测算法，无需手动设阈值 (Ch 2)
- **CMOV (Conditional Move)** — x86 条件移动指令，将控制依赖转为数据依赖，消除分支 (Ch 10)
- **CPI (Cycles Per Instruction)** — 每条指令平均消耗的时钟周期数；CPI = 1 / IPC (Ch 4)
- **CSEL / CSINC / CSNEG** — ARM 条件选择指令系列，等价于 x86 CMOV (Ch 10)
- **Dennard Scaling** — 随晶体管密度增加，单位面积功耗保持不变的定律，已于 ~2006 年失效 (Ch 1)
- **DFS (Dynamic Frequency Scaling / Turbo Boost)** — 动态频率调节：CPU 短时提升频率，但受热限制 (Ch 2, AppA)
- **DoNotOptimize** — 编译器屏障惯用法：用内联汇编阻止编译器消除被测试代码 (Ch 2)
- **DRAM / DDR / GDDR / HBM** — 不同类型的内存技术：DDR（低延迟）、GDDR/HBM（高带宽）(Ch 3)
- **DTLB (Data TLB)** — 数据翻译后备缓冲器，缓存数据地址的虚拟到物理映射 (Ch 3, 8)
- **eBPF / GAPP** — 内核可编程追踪框架，用于无侵入式性能分析 (Ch 13)
- **False Sharing** — 多核对同一缓存行的不同变量写入，导致缓存一致性协议无效 ping-pong (Ch 13)
- **Flame Graph** — Brendan Gregg 发明的可视化性能分析图，用宽度表示采样命中率 (Ch 7)
- **Frontend Bound** — TMA L1 分类：取指/译码阶段无法提供足够 µops (Ch 6)
- **FTZ / DAZ (Flush To Zero / Denormals Are Zero)** — 将亚正常浮点数刷新为零的硬件模式，避免微码辅助开销 (Ch 12)
- **Huge Pages** — 大页（x86: 2MB/1GB），减少 TLB 压力；有显式（mmap）和透明（THP）两种方式 (Ch 3, 8)
- **Hybrid Architecture** — 混合架构：大核+小核组合设计（Intel P/E-cores, Apple Firestorm/Icestorm, ARM big.LITTLE）(Ch 3)
- **IBS (Instruction Based Sampling)** — AMD 的硬件采样机制：分 IBS Fetch 和 IBS Execute 双模式 (Ch 6)
- **ILP (Instruction-Level Parallelism)** — 指令级并行：单个指令流内的并行性；受依赖链限制 (Ch 3)
- **Inlining** — 函数内联：消除调用开销，增加编译器优化范围，但增大代码体积 (Ch 9)
- **IPC (Instructions Per Cycle)** — 每周期执行的指令数；IPC = 1 / CPI；性能 = IPC × 频率 (Ch 4)
- **ISA (Instruction Set Architecture)** — 指令集架构：软硬件之间的契约 (x86-64, Armv8-A, RISC-V) (Ch 3)
- **ISPC (Intel SPMD Program Compiler)** — Intel 的 SIMD 编程语言，用 SPMD 模型生成向量化代码 (Ch 9)
- **LBR (Last Branch Record)** — Intel 硬件分支记录：后台记录最近 N 条跳转，开销 <1% (Ch 6)
- **LLVM-MCA** — LLVM Machine Code Analyzer：静态分析工具，模拟指令调度和吞吐量 (Ch 5, 12)
- **Loop Unrolling** — 循环展开：复制循环体以减少迭代开销，增加指令级并行性 (Ch 9)
- **Macrofusion** — 同一指令内的 µop 融合（如 cmp + jmp → 单 µop）(Ch 4)
- **Microfusion** — 跨指令的 µop 融合（如 memory + arithmetic → 单 µop）(Ch 4)
- **MLC (Memory Latency Checker)** — Intel 内存延迟/带宽测量工具 (Ch 4)
- **MLP (Memory-Level Parallelism)** — 内存级并行：平均并发在途的 L1 miss demand loads (Ch 4)
- **MPKI (Misses Per Kilo Instruction)** — 每千条指令缓存缺失次数：归一化指标，消除指令数差异 (Ch 4)
- **OOO (Out-of-Order Execution)** — 乱序执行：指令可无序进入执行阶段，但按程序顺序退休 (Ch 3)
- **PGO (Profile-Guided Optimization)** — 基于运行时 profile 数据的编译优化 (Ch 11)
- **PEBS (Precise Event-Based Sampling)** — Intel 的精确事件采样：消除 skid，可获取寄存器值和内存地址 (Ch 6)
- **PMU (Performance Monitoring Unit)** — 性能监控单元：硬件计数器 PMCs，用于事件采集 (Ch 3, 5)
- **PMC (Performance Monitoring Counter)** — 性能监控计数器：可编程事件如周期、指令、缓存缺失等 (Ch 5)
- **Retiring** — TMA L1 分类：µop 正常退休的 pipeline slot 比例 (Ch 6)
- **ROB (Reorder Buffer)** — 重排序缓冲区：跟踪指令状态，大小决定 OOO 前瞻深度 (Ch 3)
- **Roofline Model** — 性能上限模型：绘制运算强度 vs. FLOP/s，识别内存带宽或计算瓶颈 (Ch 5)
- **SIMD (Single Instruction Multiple Data)** — 单指令多数据：一条指令并行处理多个数据元素 (Ch 3, 9)
- **SMT (Simultaneous Multithreading)** — 同时多线程：多个逻辑核共享一个物理核的执行资源 (Ch 3, 13)
- **SPE (Statistical Profiling Extension)** — ARM 的硬件采样机制：集 IBS 两种能力和更细粒度的延迟分解 (Ch 6)
- **Speculative Execution** — 推测执行：CPU 预测分支方向提前执行指令，误预测时冲刷流水线 (Ch 3)
- **SVE (Scalable Vector Extension)** — ARM 可变长度向量扩展：向量长度编译时未知 (Ch 3)
- **TAGE Predictor** — 当前最先进的分支预测算法，误预测率 < 3 per 1000 (Ch 3)
- **TLB (Translation Lookaside Buffer)** — 翻译后备缓冲器：虚拟→物理地址映射缓存 (Ch 3)
- **TMA (Top-down Microarchitecture Analysis)** — 自顶向下微架构分析：将瓶颈归因到 Frontend/Backend/Retiring/Bad Speculation (Ch 6)
- **Tomasulo Algorithm** — 动态调度算法：通过寄存器重命名消除假依赖，支持乱序执行 (Ch 3)
- **TSC (Time Stamp Counter)** — 硬件时间戳计数器：`__rdtsc()`，~5ns 延迟，用于短事件计时 (Ch 2)
- **UICA (Intel Architecture Code Analyzer)** — Intel 静态性能分析工具的前身，LLVM-MCA 的后继 (Ch 5)
- **Vectorization / Autovectorization** — 代码向量化：利用 SIMD 指令编译器自动或手动转换标量循环 (Ch 9)
- **VTune Profiler** — Intel 的商业性能分析工具，集成 TMA、微架构探索等功能 (Ch 7)
