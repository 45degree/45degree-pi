# Glossary of Key C++ Terms

- **AAA Style (Almost Always Auto)**: A coding style where `auto` is the default for variable declarations, with exceptions requiring explicit justification (e.g., proxy types, readability). (ch02)
- **alias declaration (`using`)**: C++11 syntax `using X = Y;` that replaces `typedef`, additionally supporting alias templates (parameterized type aliases) which `typedef` cannot express. (ch03)
- **alias template**: A `using` declaration with template parameters, eliminating the `::type` suffix and `typename` prefix required by `typedef`-based trait wrappers. (ch03)
- **array decay**: The implicit conversion of an array to a pointer to its first element, which occurs in pass-by-value template deduction and `auto` deduction (unless the array is captured by reference). (ch01)
- **`auto`**: A type deduction keyword that infers the variable's type from its initializer using template type deduction rules, with one exception: braced initializers deduce to `std::initializer_list<T>`. (ch01, ch02)
- **`auto&&`**: A universal reference declared via `auto`, binding to lvalues as `T&` and to rvalues as `T&&` via reference collapsing; essential for generic lambdas and forwarding. (ch01, ch05)
- **braced initialization (`{}`)**: Uniform initialization syntax that prevents narrowing conversions and the most vexing parse, but may be hijacked by `std::initializer_list` constructors in overload resolution. (ch03)
- **`cbegin` / `cend`**: C++11 member functions returning `const_iterator` from both const and non-const containers, making read-only iteration straightforward. (ch03)
- **condition variable**: A synchronization primitive for repeated notifications between threads; suffers from spurious wakeups and missed wakeups; use `std::promise`/`std::future` instead for one-shot events. (ch07)
- **`const` member function thread safety**: The requirement to protect `mutable` data members accessed by `const` functions with `std::mutex` or `std::atomic` to avoid data races in multithreaded contexts. (ch03)
- **`const_iterator`**: An iterator that prohibits modification of the pointed-to element; preferred over plain `iterator` when only reading, enabled by `cbegin`/`cend` in C++11. (ch03)
- **`constexpr`**: A specifier for variables and functions whose values can be computed at compile time; C++14 relaxes restrictions, allowing loops and local variables in `constexpr` functions. (ch03)
- **control block**: A heap-allocated structure shared by all `std::shared_ptr` and `std::weak_ptr` instances referencing the same object, containing strong reference count, weak count, and a type-erased custom deleter. (ch04)
- **copy elision**: A compiler optimization that eliminates copy/move operations by constructing return values directly in the caller's context; applying `std::move` to a return value can disable this optimization (RVO). (ch05)
- **dangling**: A pointer or reference that refers to an object whose lifetime has ended; common causes include returning references to locals, proxy objects outliving their containers, and default reference captures in lambdas. (ch05, ch06)
- **`decltype`**: An operator returning the exact declared type of an expression, preserving references and cv-qualifiers; `decltype((x))` on a parenthesized lvalue adds `&` (a common pitfall). (ch01)
- **`decltype(auto)`**: A C++14 return type specifier that deduces the type using `decltype` rules (preserving references) rather than template deduction rules; essential for perfect-returning forwarding functions. (ch01)
- **default capture (`[&]`, `[=]`)**: Lambda capture modes that implicitly capture all referenced variables; `[&]` hides dangling reference bugs, and `[=]` misleadingly captures `this` by reference for member access. (ch06)
- **deleted function (`= delete`)**: C++11 syntax that suppresses a function at compile time, applicable to any function (member, non-member, template specialization)—a superior replacement for the C++98 private-undefined trick. (ch03)
- **`emplace` / `emplace_back`**: Container methods that construct elements directly in-place from forwarded constructor arguments, eliminating temporary objects and moves; beware of explicit constructors and `shared_ptr` resource management pitfalls. (ch08)
- **`enable_if`**: A template metaprogramming tool (`std::enable_if`) used to conditionally disable template overloads, most commonly to constrain universal reference overloads and avoid hijacking copy/move constructors. (ch05)
- **`enum class` (scoped enum)**: An enumeration type that scopes enumerators, prevents implicit integer conversions, supports forward declaration, and allows explicit underlying type specification. (ch03)
- **explicitly typed initializer idiom**: The pattern `auto x = static_cast<T>(expr);` to force `auto` to deduce the intended type, primarily used to work around proxy class deduction (e.g., `std::vector<bool>::reference`). (ch02)
- **forwarding reference**: See *universal reference*. (ch05)
- **function decay**: The implicit conversion of a function to a function pointer that occurs in pass-by-value template deduction unless the function is captured by reference. (ch01)
- **generic lambda**: A C++14 lambda with `auto` parameters, enabling polymorphic function objects; requires `decltype(param)` for `std::forward` to correctly preserve value categories. (ch06)
- **init capture (`[x = expr]`)**: C++14 generalized lambda capture that initializes a new data member from an arbitrary expression, enabling move capture of move-only types (e.g., `std::unique_ptr`) into closures. (ch06)
- **`make_shared` / `make_unique`**: Factory functions that construct objects and wrap them in smart pointers in a single expression, providing exception safety, eliminating type repetition, and (for `make_shared`) allocating the object and control block together. (ch04)
- **most vexing parse**: A C++ parsing ambiguity where a declaration intended as a variable definition with constructor arguments is interpreted as a function declaration; braced initialization `{}` avoids it. (ch03)
- **move semantics**: A language feature enabling the transfer of resources from one object to another via rvalue references, avoiding deep copies and enabling efficient resource management. (ch05)
- **`mutable`**: A specifier allowing a data member to be modified inside `const` member functions; commonly used for caching, lazy evaluation, and synchronization primitives (`std::mutex`, `std::atomic`). (ch03)
- **narrowing conversion**: An implicit conversion that loses information (e.g., `double` to `int`); forbidden by braced initialization `{}` but silently permitted by parenthesized initialization `()`. (ch03)
- **`noexcept`**: A specifier declaring that a function will not throw exceptions; essential for move constructors to enable `std::vector` reallocation optimizations and for improving generated code. (ch03)
- **`nullptr`**: A keyword of type `std::nullptr_t` representing a null pointer; preferred over `0` and `NULL` because it is not an integer type, ensuring correct overload resolution and template deduction. (ch03)
- **`override`**: A contextual keyword that marks a derived class function as overriding a base class virtual function, enabling compile-time verification of the override's correctness (signature, constness, ref-qualifiers). (ch03)
- **perfect forwarding**: The technique of passing function arguments to another function while preserving their value category (lvalueness/rvalueness), achieved via universal references and `std::forward`. (ch05)
- **perfect forwarding constructor**: A constructor template taking a universal reference that can unintentionally hijack calls to the copy and move constructors for non-const arguments; typically constrained with `enable_if`. (ch05)
- **perfect forwarding failure cases**: Five known scenarios where perfect forwarding fails: braced initializers, `0`/`NULL` as null pointers, declaration-only `static const` members, overloaded function/template names, and bitfields. (ch05)
- **Pimpl (Pointer to Implementation)**: An idiom that hides a class's implementation details behind a pointer to a forward-declared struct in the header, reducing compilation dependencies; with `std::unique_ptr`, requires special member functions to be defined in the `.cpp` file. (ch04)
- **proxy class**: A type that simulates another type's behavior but is not that type itself (e.g., `std::vector<bool>::reference`); causes `auto` to deduce the wrong type, leading to dangling pointers if the proxy outlives its container. (ch02)
- **RAII thread wrapper (ThreadRAII)**: A custom class that ensures a `std::thread` is either `join()`ed or `detach()`ed before destruction, preventing `std::terminate` on all code paths including exceptions. (ch07)
- **reference collapsing**: The rule that reduces double references (`T& &` → `T&`, `T&& &` → `T&`, `T& &&` → `T&`, `T&& &&` → `T&&`), occurring during template instantiation, `auto` deduction, and `typedef`/`decltype` expansion; the foundation of universal references. (ch05)
- **Return Value Optimization (RVO)**: A compiler optimization that constructs a return value directly at the call site, eliminating copies; applying `std::move` to a local return value can disable RVO. (ch05)
- **Rule of Five / Rule of Zero**: If any of destructor, copy, or move operations is user-declared, all five should be explicitly declared or `= default`ed (Rule of Five); ideally, design classes so none are needed (Rule of Zero). (ch03)
- **rvalue reference (`T&&`)**: A reference type that binds only to rvalues (temporaries, `std::move` results); used to implement move semantics, but a named rvalue reference parameter is itself an lvalue. (ch05)
- **SFINAE (Substitution Failure Is Not An Error)**: A template metaprogramming principle where invalid substitutions during overload resolution silently discard the overload rather than causing a compilation error; used with `std::enable_if` to constrain templates. (ch05)
- **`std::async`**: A task-based concurrency function that returns a `std::future`; handles thread scheduling, return values, and exception propagation automatically; prefer task-based programming over manual `std::thread` creation. (ch07)
- **`std::atomic`**: A template providing lock-free atomic operations for variables shared across threads, guaranteeing atomicity and memory ordering; used for concurrency, not for special memory (use `volatile` for that). (ch03, ch07)
- **`std::bind`**: A C++98 function for partial application and adaptation; superseded by lambdas for readability, inlining, and overload resolution, but still useful for C++11 move capture emulation. (ch06)
- **`std::forward`**: A conditional cast that converts its argument to an rvalue only if the argument was originally bound to an rvalue; used exclusively with universal references to implement perfect forwarding. (ch05)
- **`std::initializer_list` hijack**: A surprising overload resolution behavior where `std::initializer_list` constructors are strongly preferred during braced initialization, even when other constructors appear to be a better match. (ch03)
- **`std::launch::async`**: A launch policy for `std::async` guaranteeing the task runs on a separate thread immediately; the default policy (`async | deferred`) makes execution timing unpredictable. (ch07)
- **`std::move`**: An unconditional cast that converts its argument to an rvalue reference; it performs no actual move, merely enables move semantics; applying it to a `const` object silently invokes the copy constructor instead. (ch05)
- **`std::shared_ptr`**: A reference-counted smart pointer for shared ownership; twice the size of a raw pointer, with atomic reference-count operations and a type-erased custom deleter in a shared control block. (ch04)
- **`std::thread`**: A low-level concurrency primitive representing a single thread of execution; its destructor calls `std::terminate` if the thread is still joinable, requiring manual `join()`/`detach()` management. (ch07)
- **`std::unique_ptr`**: A move-only smart pointer for exclusive ownership; same size and performance as raw pointers with the default deleter; the ideal factory return type because it easily converts to `std::shared_ptr`. (ch04)
- **`std::weak_ptr`**: A non-owning observer of a `std::shared_ptr`-managed object, used for caching, observer patterns, and breaking `std::shared_ptr` cycles; access requires atomically locking via `lock()`. (ch04)
- **tag dispatch**: A technique for routing calls to different function implementations based on type traits (e.g., `std::is_integral`) via tag struct instances, avoiding overload ambiguity with universal references. (ch05)
- **task-based programming**: A concurrency model using `std::async` and futures rather than raw `std::thread`s; the runtime handles load balancing, oversubscription avoidance, and exception propagation. (ch07)
- **template type deduction (three cases)**: The rules governing how `T` is deduced from `ParamType`: Case 1 — reference/pointer (strip reference, pattern-match), Case 2 — universal reference (lvalue → `T&`, rvalue → `T`), Case 3 — pass-by-value (strip ref, cv-qualifiers, decay arrays/functions). (ch01)
- **thread pool**: An implicit resource managed by `std::async`'s task-based execution, avoiding thread oversubscription and enabling work-stealing across tasks; not directly exposed as a standalone C++11/14 API. (ch07)
- **`thread_local`**: A storage class specifier giving each thread its own independent instance of a variable; breaks with `std::async`'s default launch policy when tasks may be deferred and run on the calling thread. (ch07)
- **universal reference (`T&&` where `T` is deduced)**: A function template parameter or `auto&&` declaration that can bind to both lvalues and rvalues; with `std::forward`, it enables perfect forwarding. (ch05)
- **value category (lvalue / rvalue)**: The classification of expressions based on identity and movability; lvalues have identity (can take address), rvalues are temporary (can be moved from); a function parameter is always an lvalue regardless of its declared type. (ch05)
- **`volatile`**: A qualifier telling the compiler not to optimize away reads or writes to a variable, intended for memory-mapped I/O and signal handlers; provides no atomicity or ordering guarantees for concurrency. (ch07)
